# PhoneNAS

把手机 WebDAV 挂载为 Windows 盘符，用原生中文工作台管理多个文件夹，并在公司、手机和家里电脑之间**安全接力文件**。

Windows 10/11 x64 · Python + PySide6 · rclone · WinFsp · 无广告

## 维护候选：手机托管与 Windows HTTPS 接力

本分支的 Windows 1.2.4 候选支持在设置中为一条独立的 PhoneNAS HTTPS 连接导入手机的公开证书并核对指纹，挂载、传输和同步保护共用同一连接身份。新的服务端把慢上传暂存和文件发布分开；上传中仍可浏览已提交的文件。见[验收边界](docs/ANDROID-ACCEPTANCE.md)。候选未替换现场旧服务，不是以下桌面 1.2.3 正式发布。

## 1.2.3：文件名校验与报错定位

修复正常 Unicode 名称被整类误拦：私用区字符、未分配码位及文字/Emoji 连接符可原样处理，不自动改名或跳过。控制字符、双向文字控制、路径穿越、Windows 保留名及大小写/Unicode 别名冲突仍阻止执行。

扫描失败时指出本地或手机目录、具体相对路径和问题字符码位；不再把工作文件的名称问题笼统称为“历史文件路径无效”。差异列表将不可见字符显示为 `<U+XXXX>`，实际传输仍使用原名。升级不重置任务、基线或锁，不自动上传。

## 1.2.2：进度对应实际阶段

上传和下载明确区分 **暂存、内容复核、写入目标、保留旧文件、补齐目录和最终校验**。字节百分比只表示当前复制阶段，不代表整个任务完成；例如“下载到暂存区 · 本阶段 100%”时，接收目录可能仍未写入。

进入校验或收尾后立即清除上一阶段百分比，显示当前阶段及已用时；目录处理显示实际核对数量。只有完成内容验证、保存结果并释放任务锁后，才报告任务完成。减少对已存在或已由成功复制创建的目录重复启动 rclone，不减少完整 SHA256 复核、不改变基线或冲突保护。

## 本机手动上传与下载

同一张任务卡直接提供 **“上传到手机” / “下载到本地”** 两个按钮，先只读查看差异，确认后才执行。不需要为同一个文件夹创建两条相反任务。

在任务设置的“计划与保留”中关闭 **“按计划自动执行”**，保留“启用此任务”，即可永久设为 **仅手动**；重启软件也不会恢复自动计划。这与临时“暂停自动计划”不同。

两边原本已存在且内容相同的目录，可以明确核对并建立首次共同基线；该操作只写控制信息和本机基线，不传输、覆盖、删除工作文件或清理历史。两边不一致时不能用此方式绕过首次接管保护。

## 1.2 工作台

- **明确方向**：每任务选择“上传发布”或“下载接收”，显示来源、目标及历史所在位置。
- **多文件夹、独立计划**：单个或批量添加发布任务；按任务设置频率、保留天数与排除规则，全局串行去重执行。
- **接力编辑**：家里接收后可编辑；未交回的本地改动会阻止后续拉取，不会静默覆盖。交回是明确的手动操作，不是后台双向同步。
- **防旧副本覆盖**：家里交回后，公司自动上传发现手机新批次就停止，需先核对并接收手机更新。
- **内容基线与差异确认**：比较真实 SHA256 内容，确认绑定文件内容和批次；不能仅凭文件大小、修改时间、数量或“上次成功”判断两端一致。
- **两侧历史**：上传替换/删除前的旧文件留在手机；下载及公司接收更新前的旧文件留在本地独立目录。离线可浏览、恢复本地历史。
- **取消与中断保护**：暂停自动计划不停止当前任务；取消当前操作需确认。未完成写入不会记为成功，不清历史，原电脑可明确核对后续作。
- **A 清爽工作台**：修复卡片状态裁切和搜索图标偏位；“预演”改名“查看差异”；主卡显示中文阶段/真实统计，原始输出进入日志。
- **共享连接与盘符**：新配置推荐只读挂载；挂载与同步互不依赖。内置 rclone 1.76.0、WinFsp 2.1.25156。
- **配置保护**：Windows DPAPI 用户级密码加密；导出剔除密码；v1/v2 升级到 v3，首次保存前保留原始配置备份。

> **历史文件不是完整快照。** 时间批次只包含该轮被覆盖、删除的旧文件。“恢复这批旧文件”不会把文件夹还原到那个时刻的完整状态。

## 推荐用法：公司发布，家里接收

```text
公司电脑 ── 上传发布 ──> 手机当前镜像 ── 下载接收 ──> 家里电脑
   ↑                         ↑                           │
   └── 手动接收手机更新 ──────┴──── 手动交回本地修改 ─────┘
```

### 先建立公司基线

1. **先暂停家里现有的旧上传任务。不要把家里副本直接当作公司最新来源。**
2. 分别保留、比较公司、手机和家里现有内容，确定以公司哪份文件为起点。
3. 公司端添加“上传发布”任务，核对本地来源、手机镜像目录、手机历史目录及排除规则。
4. 点“查看差异”。首次发布/接管必须明确确认；旧配置的成功时间不构成内容授权。
5. 完成并校验后，手机数据集才可供其他电脑接收。

本轮开发不自动执行上述真实迁移，不自动反转现有任务，不删除旧文件。

### 家里接收及编辑

1. 保存同一手机连接；添加“下载接收”任务。
2. 明确选择**已有手机镜像目录**，与公司使用同一数据集、远端历史路径及排除规则。目录选择器只读，不创建远端目录。
3. 选择新的空本地接收目录和独立的本地历史目录，先核对差异，再启用及接收。新接收任务默认停用。已有两端内容完全相同的目录，可经明确校验初始化共同基线，无需覆盖文件。
4. 接收成功后可在本地编辑。新增、内容修改和删除都属于待交回改动。
5. 有本地改动时自动拉取停止；点“上传到手机”（原“交回本地修改…”），检查全部差异并确认。
6. 手机自共同基线已有变化时不允许直接交回，即使两端改的是不同文件也先停止，不做自动合并。

不建议在受任务维护的手机镜像内直接编辑。需要普通自由访问的文件可放在镜像外。

### 回到公司

- 手机有家里交回的新修改时，公司旧副本不能自动覆盖它。
- 若公司本地仍与共同基线一致，点“下载到本地”（原“接收手机更新…”），核对后下载；旧本地文件进入本地历史。
- 如果公司本地也有修改，软件阻止直接覆盖。先另存两端工作、核对处理；代码建议用 Git 合并，不把历史保留当作冲突合并。
- 接收完成后恢复原来的“上传发布”用途，无需把任务来回改方向。

## 安全边界与性能

- 自动执行只沿任务默认方向；交回、接收手机更新和续作均为明确操作，没有 `bisync` 或隐式自动双向。
- 数据集控制信息位于手机 `.phonenas/datasets/<数据集ID>/`，互斥目录在 `.phonenas/locks/`。PhoneNAS 用独占 MKCOL 协调读写；不支持该能力时停止，不用非独占 `mkdir` 假装获得锁。
- 发布中、校验失败、异常来源或外部内容与批次不一致时停止。**通用 WebDAV 不是完整目录原子快照。** 其他客户端、可写挂载或人为绕过控制仍可能改写文件；内容复核能检测很多变化，但不承诺替代服务端事务或全盘快照。
- 普通 WebDAV 可能没有服务器内容哈希，此时需下载读取内容作校验。差异传输通常只发送变化文件，但扫描/校验不是零带宽；大目录会明显慢于只比较时间和大小。
- 变化文件先暂存并核对内容，再改写目标；电脑需为本轮变化文件和历史保留预留磁盘空间。
- 手机来源缺失、不可读或异常空不会变成正常“清空家里目录”。文件/目录换型、大小写和 Unicode 别名等不安全路径须先人工处理。
- 源、目标、历史与控制目录互相隔离；缺盘不能视为空目录。删除保护依然覆盖大量删除、来源骤减及首次接管。
- **取消不回滚已经完成的写入。** 未完成操作会保存内容意图；写入中断可能保留原所有权锁。只能原电脑点“继续未完成操作…”重新核对；来源又变、目标有新修改或无法证明所有权时停止。不会按超时自动抢锁；丢失原电脑/记录时应先备份两端并人工核对。

## 挂载、计划与历史

- 只读挂载仅限制经此盘符写入；不阻止明确的上传/交回，也不改变服务器账号权限。本版接收任务也需在 `.phonenas` 控制目录建立互斥锁，因此完全只读的 WebDAV 账号不能执行协调接收。服务器若支持按目录授权，可将镜像设为只读、控制目录保留写权限；交回还需镜像及手机历史的写权限。
- 新配置只读挂载默认开启；旧 v1/v2 配置保留原有可写行为，建议在设置中主动切换只读。
- 任务频率 **1–1440 分钟**，历史保留 **1–3650 天**（默认 30 天）。编辑与向导范围一致，越界配置拒绝，不静默钳制。
- “暂停自动计划”只暂停后续自动派发，当前操作继续；启用任务仍可明确手动执行。“停用任务”会禁止该任务的自动及手动写入，但可只读查看差异。
- 移除任务只移除配置，手机镜像、本地文件和历史均保留。
- 历史页先选择任务，再选择“手机发布历史”或“本地接收历史”。恢复在所选父目录下新建独占子目录，不覆盖当前工作文件。
- 永久删除需确认；过期历史只在对应方向成功后按任务清理。失败、取消和未交回改动不会触发过期清理。
- 挂载仅说明本机盘符进程就绪，不等于独立的“手机在线”检测。PhoneNAS 不监控或重启手机 Termux、WebDAV 或 Tailscale，不创建 PC 手机保活任务。

## 配置升级、导入与日志

- 安装/目录版：`%APPDATA%\PhoneNAS\config.json`，日志 `logs\`，内容基线/未完成意图 `baselines\`。
- 便携版：EXE 旁有 `portable.flag` 时使用 `data\`；`PHONENAS_DATA_DIR` 显式覆盖优先。
- v1/v2 加载只在内存迁移，首次保存前分别保留 `config.v1-backup` / `config.v2-backup` 原始字节。已有任务保留原方向、路径和启用状态。
- 损坏或未来配置拒绝自动执行与覆盖；合法导入替换前保留原件。
- 导出不含密码，不导出设备内容基线。导入会更换本机基线身份；换电脑必须重新建立共同基线，不把另一台电脑的成功记录当作授权。
- DPAPI 密文不能跨 Windows 用户解密。配置、日志、基线及 rclone 凭据都不应公开上传。
