# PhoneNAS 多文件夹 + 界面重构草案

状态：**待用户选择原型后再实施**。本文不是已经完成的桌面功能。本次没有更改正式应用、安装目录、现有配置、同步任务或手机文件。

## 1. 推荐交互

推荐 **A 清爽工作台作为主界面**，吸收 B 的来源 → 镜像展示到任务编辑器。若需要管理大量文件夹，再提供 C 的紧凑列表视图；首轮不必同时实现三个完整桌面布局。

- 原来的“镜像”单表单改为“同步任务”。支持一次选多个文件夹，为每个文件夹创建独立任务。
- 每个任务展示名称、本地路径、启停状态、上次/下次执行、同步结果；可单独同步、预演、编辑、暂停、移除。
- 编辑窗口分成“文件夹 / 计划与保留 / 排除规则”。常用规则用预设，原始匹配文本折叠到高级设置。
- 同步频率、版本保留、排除规则都可以逐任务独立设置；批量添加时采用默认值，之后分别调整。
- 历史页先选任务，再看其时间戳目录；日志和执行状态始终带任务名称。
- NAS 账号、连接、盘符、开机自启仍是全局设置，不需要每个任务单独填写。
- 控件风格统一指定：下拉列表、数字输入箭头、菜单、禁用/焦点态都明确定义，避免截图中的深色弹出层/浅色文字冲突与原生控件割裂。保持 PySide6，不为正式版新增浏览器运行时。

## 2. 数据模型：一项镜像 → 一组任务

配置升级为 `version: 2`。保留全局 `nas`、`mount`、`app`，把单例 `mirror` 迁为 `mirror.tasks[]`。

每个任务至少包含：

- `id`：稳定身份，不随改名变化。
- `name`、`enabled`。
- `local_path`、`remote_path`、`versions_path`。
- `interval_minutes`、`retention_days`。
- `exclude_preset`、`excludes`。
- `last_sync_at`：独立的最近成功时间。

任务的运行/排队/失败状态和下次执行时间放内存，不把短暂状态当配置真相。worker 接收执行前冻结的任务快照，避免运行中编辑导致同步写 A 目录、清理却指向 B 目录。

### 目录示例

保留现有工作任务的路径，不搬动已有文件：

```text
backup/
  work/                         # 现有工作文件的当前镜像
  work-versions/<时间戳>/        # 现有工作文件的旧文件
  product-docs/
    mirror/                     # 产品文档镜像
    versions/<时间戳>/          # 仅产品文档的旧文件
  design-assets/
    mirror/
    versions/<时间戳>/
```

**不能把多个不同本地来源都 sync 到同一个远端目录。** `rclone sync` 会按当前来源删除目标里多余的文件；任务必须相互隔离。

新任务的自动目录使用稳定 ID，显示名称可以自由修改。换电脑部署时建议加设备命名空间，或明确只允许一台电脑写同一个镜像目录，避免多台电脑互相镜像删除。

## 3. 调度：独立计划，统一队列

- 一个全局计时器，维护每个任务的到期时间。
- 默认一次只执行一个同步任务，避免手机 I/O、网络、版本清理互相抢占。
- 自动触发按任务 ID 去重，不把错过的每个周期都堆起来；手动“同步全部”只调度启用的任务。
- 单个任务失败不阻塞后续任务。下次按策略再试，不形成失败任务的立即死循环。
- 暂停不强杀当前写入中的任务；退出时停止继续派发。
- NAS 连接配置导入/变更在空闲时生效，不能中途替换运行中共享的 rclone 配置。

## 4. 安全边界

1. 本地源为空字符串、缺失、不可读、不是目录时，阻止该任务同步和历史清理；不能把缺失源当成空目录镜像删除。
2. 不允许把 PhoneNAS 挂载的盘作为来源，防止自己同步自己。重复/父子本地来源要提示。
3. 规范化后，所有任务的镜像根和历史根不得相同或互相包含。按路径段判断，不用简单字符串前缀。
4. 源突然变空、大量删除，或远端更换为已有未知目录时，先预演/明确确认，再执行。
5. **移除任务默认只移除配置，不删除手机镜像或历史。** 数据清理必须是另外一个明确操作。
6. 同一任务同步、恢复与历史清理要互斥。恢复默认到新目录，覆盖当前文件需确认，并校验相对路径不越界。

## 5. 旧配置与现有数据

- 先备份配置，再把 v1 的 `mirror.*` 原样转成第一个任务。
- 保留原 URL、凭据、盘符、频率、保留天数、实际排除列表、成功时间和原远端路径。
- 不搬动手机文件，不因迁移本身重传基线；正常下次同步仍只传差异。
- 启动读取与配置导入共用幂等迁移；v2 的空任务列表应合法，不能擅自补一个启用的默认任务。
- 未知未来配置版本或损坏配置应阻止自动同步，不能静默降级成可执行默认值。
- 导出继续不含密码；在另一台电脑导入后重新填写凭据。

## 6. “版本”的准确含义

当前 `--backup-dir` 是**变化前旧文件留存**，不是完整时间点快照。

因此把“版本”页改称“历史文件”，“恢复整个版本”改为“恢复这批旧文件”。它不会自动重建当时整个文件夹的完整状态。如果之后需要真正的时间点恢复，需单独设计快照/索引与恢复算法，不在 UI 上假装已支持。

## 7. 主要源码改造点

- `app/core/config.py`：任务模型、按 ID 访问、配置迁移与统一校验。
- `app/core/sync.py`：按任务构建参数、冻结快照、带任务 ID 的进度/结果、任务范围的清理。
- `app/core/scheduler.py`：各任务独立计划，串行去重队列。
- `app/ui/main_window.py`：队列协调、逐任务状态、启动补跑、退出/配置导入处理。
- `app/ui/pages/mirror.py`：任务列表、添加/编辑/启停/预演。
- `app/ui/pages/versions.py`：按任务隔离的浏览与恢复。
- `app/ui/pages/status.py`、`app/ui/wizard.py`、`app/ui/pages/settings.py`：总览、首次建任务、导入后刷新。
- `app/ui/style.qss`：统一色彩、间距、控件状态与弹出层样式，验证 Windows 深浅主题及 DPI。

## 8. 分阶段实施与验收

1. 确定一个主视觉与任务交互，不立即重写已有安装。
2. 数据层与无损迁移；测试密码保留/导出脱敏、旧字段迁移、空列表和损坏配置处理。
3. 多任务执行/调度；测试串行去重、暂停、失败继续、运行中编辑隔离。
4. 桌面 UI 与向导、历史、日志联动；验证不同窗口尺寸与缩放比例。
5. 用两个独立临时目录验证新增、更新、删除、旧文件恢复、保留清理互不影响；模拟缺盘和远端路径冲突。
6. 用户同意后再用真实工作文件夹做预演、打包安装与发布。更新安装包/Release 是单独交付步骤。

继续不包含：手机服务监控、PC 侧保活、修改手机自启策略、CC Switch 原生双向同步管理、多 NAS 配置、自动更新。
