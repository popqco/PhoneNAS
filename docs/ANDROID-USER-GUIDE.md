# PhoneNAS 手机端 · 文件服务端部署说明

> 这是存放文件的手机的服务端说明。0.4.2 在一台 vivo 上通过了插电熄屏场景，范围见[验收记录](ANDROID-ACCEPTANCE.md)。**想用另一台手机打开云盘？** 在访问手机安装独立的 [PhoneNAS 云盘客户端](ANDROID-CLOUD-CLIENT.md)，不用再配置一套文件服务。

## 与既有部署的关系

本应用使用独立包 `com.phonenas.server.probe`。不会安装/登录/接管 Tailscale，不会停止原有 Termux / WsgiDAV，不会迁移工作目录、数据集身份、历史或电脑基线。不要让两个服务同时接管同一个工作数据集。

手机服务本身不依赖 USB、电脑脚本或电脑在线。电脑只在主动访问文件或验收时作为客户端，不承担保活、自愈或监控。

## 1. 选择共享

1. 先停止服务并等待确认关闭，进入“共享”。默认“隔离演示”仅导出本应用的 `/test/` 和 `/readonly/`，不是你的个人目录。
2. 对真实公共目录，打开本应用的“文件访问授权”，经系统页面允许“所有文件访问”。这是较广的权限；应用仍只导出你逐项添加且启用的目录。拒绝或撤销时不会改用其他目录。
3. 通过系统目录选择器选择**手机内置存储中的现有独立子目录**，填写稳定 URL 名称，例如 `documents`。默认只读；需要接力发布时再明确设为可读写。
4. 添加所需共享并切换到“自定义目录”。不允许整个存储、`Android`、应用私有目录、重叠的父子目录、链接或其他存储提供者。自定义配置失败时不会悄悄回退演示目录。
5. 修改权限、禁用或移除共享同样需要先停止。**移除只撤销导出，不删目录、文件、历史或锁。** 启用自定义模式至少需要一个可访问且启用的目录。

普通上传不会清空电脑上的来源文件夹。手机外部文件管理器的变更会从真实文件读取；编辑完成后再进行接力，不保证跨多个文件的原子快照。

**公共存储文件名限制：** 当前 vivo 的 Android 公共存储实际允许中文、空格、`%` 和 `#`，但系统拒绝创建包含 `?` 的文件名（独立 ADB 创建也被系统拒绝）。应用不会擅自改名、藏入私有存储或伪装上传成功；此类请求失败并保持旧数据完整。电脑 Windows 本身也不支持 `?` 文件名；跨其他平台时请先核对命名兼容性。此限制不被写成“任意文件名合同全部通过”。

## 2. 启用安全远程访问

1. 保留独立官方 Tailscale，先在其界面核对手机 IPv4。
2. 共享页“重新观察地址”，确认观察到的地址与 Tailscale 一致后明确保存。应用只绑定这个固定 VPN IPv4 的 **HTTPS 18889**，不绑定 `0.0.0.0`、LAN 或公网。系统网络观察不能自动证明 VPN 所有者。
3. 明确启动服务。首页分别显示本机监听和 HTTPS 监听；“监听存在”不等于电脑已连通。
4. 从首页导出**公开服务器证书**并核对显示的 SHA-256。在授权客户端为这一个连接配置该证书信任。**不要关闭 TLS 校验、不要使用 `--insecure`，也不要把自签证书当作全系统任意站点的信任根。**
5. 配对地址使用服务根 `https://<手机固定 Tailscale IPv4>:18889`，不附加共享路径。用户名为 `phonenas`，随机强密码仅在首页明确点击后显示；离开页面自动隐藏，不自动复制。
6. Windows 维护候选在「设置 → NAS 连接」勾选「使用 PhoneNAS 手机端的专用 HTTPS 证书」，导入公开 PEM，按手机页面核对并输入指纹，再测试、保存。修改地址、账号或指纹需要重新输入密码，旧配置、数据集及同步保护不会自动迁移。测试连接只证实目录可列举；同步还要保护锁与内容校验。新增同步任务须选择指定的读写共享下互相独立的 `mirror`、`versions` 相对路径（如 `work/mirror`、`work/versions`），不要让普通互传所在目录包含它们。旧 Windows 1.2.3 本身不支持这个配对入口。

证书私钥与加密凭据保存在应用私有存储。证书稳定复用；损坏、过期、地址不匹配时阻塞，不自动换身份。仅回环 HTTP `127.0.0.1:18888` 不对 LAN 开放；USB 转发不是服务运行条件。

固定 VPN 暂未就绪时只运行本机入口并显示等待，不改绑其他地址。失去固定地址时撤销远程访问；重新具备条件后须有序关闭/重建，不能同时出现两个操作同一目录的文件内核。

## 3. 后台与恢复

- 允许文件服务通知，保留清晰的“停止”入口。关闭页面或划掉任务不是停止；点击页面/通知“停止”才撤销运行意愿并关闭内核。
- 在当前专用 vivo 设备上，正常系统路径为：应用信息 → 电量 → 后台耗电管理 → 允许后台耗电；以及应用信息 → 查看所有权限 → 自启动、关联启动。单变量真机测试表明，仅自启动和后台耗电允许时，系统仍会取消进程重建；本应用关联启动允许后，普通进程死亡由 Android 自动恢复成功。只调整本应用，系统可能提示耗电或变慢；不应关闭全局安全或冻结策略。这不是其他设备必然相同的保证。
- 可靠性页区分系统观察与人工核对。打开设置不代表已成功配置，也不会启动服务。
- 重启后目标是首次解锁后按运行意愿恢复，解锁前不读取密钥或文件。系统强行停止必须尊重；之后仅打开页面不能自动启动，需要明确“启动”。
- 异常恢复有上限及退避；硬错误、权限失效、目录丢失或关闭未确认会阻塞。不会自动清锁、删除数据或通过电脑反复拉起。

## 4. 记录与故障

诊断页可在停止时明确开始一组本机运行记录，再启动服务。记录只包含结构化状态、代次、计数和资源观察，最多 2 MiB，可导出，不含账号、密码、请求正文、目录或锁 token。它没有额外 HTTP 请求、唤醒或后台任务。

记录的空白、进程中断、写入失败和容量耗尽必须保留为异常/未知。**显示运行了很久不等于 72 小时持续远端可达。** 演示模式的一次性本机读取也只证明当时前台回环内容正确，自定义目录不会自动创建自检文件。

遇到“停止未确认”不要反复启动或清除应用数据；保留诊断，按提示检查。不要删除未知 `.phonenas`、锁或状态文件来解除阻塞。

## 升级与卸载

同包、同签名覆盖升级应保留凭据、共享配置和控制状态，仍须对实际包核验。公共共享文件不属于应用卸载数据，但卸载/清数据会丢失私有密钥、凭据和控制状态；这不构成安全迁移或恢复。原演示目录属于 App 专属存储，卸载会删除。

候选包和最终版本的签名、SHA-256、已测/未测项必须以实际交付记录为准。未经独立确认，不将该包切换为旧工作数据集的正式服务。
