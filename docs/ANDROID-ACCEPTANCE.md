## 维护候选：隔离验证

- 服务端 0.4.3（code 7）把上传暂存与发布分开：原版慢 PUT 暂停时同一路径的 GET 在 1 秒内无响应；新内核在相同暂存期间返回完整旧文件，独立三次目录刷新约 2.6–3.2 ms。仍按顺序写入并核对根与目标，收到完整正文才发布。条件创建不会替换别的本地写者已创建的目标；文件系统不支持安全创建时停止，不退回覆盖。
- Windows 1.2.4 候选：证书按连接绑定，用同一叶证书处理 rclone 和同步锁，过期、替换及错误地址拒绝。隔离 HTTPS 检查观察到跨端口或明文重定向没有转发凭据；rclone 在同证书下仍可处理规范的同源路径，Python 锁请求拒绝重定向。真实 WinFsp 临时只读盘符取回 2 MiB 字节并校验，写入被拒绝且盘符正常卸载，现用 `X:` 未改。
- 用真实 rclone、Windows 同步引擎及回环 TLS Go 夹具完整验证上传发布、下载接收、交回、接收更新、冲突阻断、历史旧字节和锁释放。合成共享含 8 MiB 文件及多个小文件，两端 SHA-256 匹配。另测 32 MiB 读写、64 个小文件、8 MiB 按 1 MiB/s 限速上传、只读拒绝与中断后无半文件。Windows 本机回环和模拟限速不代表 vivo 速度、局域网或异地吞吐。
- Windows 源码最终回归 245 项：243 通过、2 项因测试机缺少创建符号链接权限跳过；未放开系统策略。与本地交付的便携 ZIP 核对：解压后的实际 EXE 加载隔离证书配置，用 WinFsp 在临时只读盘符读回 1 MiB 并匹配 SHA-256，回收所用进程和盘符。没有安装程序或覆盖现有客户端。
- Android 两变体 JVM 测试各通过服务端 80 项、客户端 65 项。候选构建、lint（0 错误、保留警告）、APK v2 验签、ZIP 和原生 ELF 16 KiB 对齐通过。Go 主机合同 115 通过、1 个 Windows 链接权限场景跳过，`go vet` 通过；未运行 Go race detector。0.4.3 ARM64 服务端候选未在物理 vivo 安装，0.4.2 的 72 小时证据不能算作其验收。
- [旧机审计](LEGACY-NAS-AUDIT.md)只关联现场状态。Windows Tailscale 当时报告可见活动直连端点（私网地址；不能据此证明同一局域网拓扑）；登记了中继区不等于文件传输在走中继。Termux:Boot 有开机接收器但未通过真实重启核验。两款 Android 安装包与历史测试候选摘要吻合；新服务未启动，未确认有可安全卸载的调试残留，未卸载或删除。

## 真实传输验收还需要什么

- 分别用同一局域网、异地直连、异地中继的真实设备，用单个大文件及多个小文件记录延迟、持续速率和中断结果。现行应用没有独立 LAN 明文入口；同 Wi-Fi 的 Tailscale 直连要实际观察，不能由连接地址推断。
- 在隔离共享完成两方向 SHA-256、只读拒绝、同名保留、断线不发布半文件；Windows 另核对发布→接收→交回→冲突、历史和锁。禁止直接用真实镜像、历史、控制目录或现用 `X:` 做写入验收。
- 旧业务如果要迁移，应另行验证与旧目录的映射、严格 HTTPS、独立写者下的创建语义和回退。单次延迟不能证明旧服务高效，候选测试没有授权切换旧服务。
