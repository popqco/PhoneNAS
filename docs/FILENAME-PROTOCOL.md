# 原名协议与升级保护（1.2.4）

## 合同

- Windows 和手机之间按实际名称读写及比较文件。支持 `U+200B`、`U+007F`，不把可见控制图形当作同一文件。仍拒绝不可移植或有歧义的路径，并原样传递 rclone 排除表达式。
- 使用既有数据集 ID、锁及存储位置。不移动现有文件、不在启动时迁移旧镜像、不删除旧基线或未完成记录来绕开保护。
- 新建数据集使用协议 2；已有不带标记的非空镜像、历史或仅有旧基线时，从协议 1 保守核对。显式初始化已有镜像仍为旧协议。所有带状态的操作在已有发布记录与绑定的本机基线、续作日志之间核对版本，不混用。
- 普通协议 1 文件可在相同的命名含义、规则、内容和所有权检查下同步或续作，格式不变。若不能证明两端（含已排除的文件、空目录、任务根目录及必要的旧记录）在使用过的不同版本下解释相同，安全停止，保留原数据与锁。旧手机历史批次中无法解释的名称不被恢复或删除；手机恢复和删除必须取得相同的数据集锁。旧协议不自动清理历史，本地历史也不由手机的版本标记授权自动清理。
- 保留内容校验与确认后重扫。写入目标前检查未过滤的名称，防止现有排除规则隐藏的目标名与待写名称存在别名。已有自动计划在升级后先暂停，显式继续才恢复；手动批量同步也必须逐项确认。配置导入更换计划批准，不影响普通配置保留。

## 传输边界

rclone 1.76.0 的 `encoder.Standard` 正好是 `Slash,Ctl,Del,Dot`。本地后端配置为这个掩码时不做双向名称转换；通用 WebDAV 后端 `None` (`EncodeZero`) 时不转换。这样相同字符串可同时用于名称清单、SHA256 清单、CLI 路径、原样文件列表、归档路径及筛选。没有给 rclone 的 glob 增加转义或实现第二套匹配器。对照使用 [rclone 的固定标签实现](https://github.com/rclone/rclone/tree/v1.76.0/lib/encoder)，测试也用项目捆绑的版本。WinFsp 挂载不带这些文件操作参数。

## 状态文件

三类 JSON 仍在原位置，通过顶层 `version` 区分协议 1/2：手机 `state.json`、本机共同基线、未完成操作。目录和内容摘要计算方式不变，但名字由协议限定；预览批准也绑定协议、当前状态与续作身份。使用旧解析器不能把协议 2 当成协议 1。所有权锁格式不变，不能作为旧客户端可写兼容的依据：旧历史操作、可写挂载以及第三方 WebDAV 客户端不一定读取该标记。

1.2.3 和便携热修复 `1.2.3-hotfix1` 曾以相同版本号写下不同含义的路径，不能从名称相似、路径摘要相同或配对的子文件名猜出来源版本。旧协议验证对会被两种实现解释不同的名称采取保守拒绝。要为这样的目录使用协议 2，备份并人工确认真正的名称后，请新建一项任务，使用新的独立镜像及历史根。不要编辑旧任务去接管新目录，也不要删除其基线；没有后台转换功能。

## 回归验证

`tests/test_webdav_filenames.py` 仅启动 `127.0.0.1` 服务，用临时目录验证原名清单、暂存、上传、下载、历史和新协议续作；用独立的旧状态记录验证普通 v1 接力、续作正常及模糊状态无写入。其他测试覆盖 Windows 路径隔离、真实 Qt 事件及配置。通过本地测试不代表已验证特定手机的可用空间、网络和 WebDAV 服务实现。
